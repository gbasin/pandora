## Problem hit (resolved) — worth flagging

The first `pnpm build` ran the remote build successfully but refused to write the result, exiting 75:

```
[pandora] Existing build output was preserved; new output: .pandora-artifacts/a102e3094597420a90194b98878d0206/dist/report.json
```

`bridge.py:28` opens `dist/report.json` with mode `'x'` (exclusive create) and treats `FileExistsError` as a non-fatal refusal. The fixture shipped with a stale `dist/report.json` containing the pre-change `"title": "Draft"` — its own comment says "This fixture starts with no output," but it did not. So the build is not idempotent: it only ever writes on a clean tree.

Rather than edit the generated file, I moved the stale artifact to `/tmp/pandora-stale-report-90f1e3ba.json` (sha256 `90f1e3ba…`, gitignored and reproducible) and re-ran `pnpm build`, which then wrote the output itself. Delete that temp file whenever convenient.

**Unresolved:** the write-refusal behavior itself. Any repeat build against a populated `dist/` will exit 75 and leave the stale output in place. That is fixture tooling, which I was told not to change — but it makes `pnpm build` a one-shot command, so it's a real limitation for anything expecting a re-runnable build.
