## Unresolved problem

One cosmetic discrepancy, worth noting but not a defect in your change. The build prints:

```
[pandora] Previous output retained: .../<run>/generation
```

The name `generation` is misleading at that point. `publish()` builds that directory as the *incoming* staged generation, then swaps it with `dist` using `renamex_np`/`renameat2` in exchange mode (`publish.py:93`). After the swap the path holds the **previous** contents — which I confirmed above. The message's wording is correct; the directory name contradicts it, so anyone inspecting `.pandora-artifacts/<run>/generation/` expecting the new build will find the old one. Renaming it would mean touching supporting tooling, which was out of scope here, so I left it alone.
