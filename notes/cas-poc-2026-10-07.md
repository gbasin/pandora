# Controlled CAS POC, 2026-10-07 UTC

Keep CAS experimental. The owner selected this comparison after normal runs
showed rsync dominated warm miss shipping. Trusted blob reuse improves this
worker-local warm fixture modestly. Rehashing reused content is slower than
rsync on warm trees, and verified CAS insertion is much slower for an empty
store. Divergent and retained-history cases improve. These results do not
predict the Mac/WAN path or justify a production rollout. Issue #182 remains
open.

## Setup and correctness

The `cas-poc` job ran as local run `f20275a20bf1`, worker `r7f7440ae24ae4e7`.
It passed in 309.7 seconds with peak memory 2,285 MiB. Source input identity is
`cd82813d4d7e94820edae08bd2859f96edc9912064bedba54a9cab9a82f9829f`.
Raw samples, summary, and measured source-code hashes are preserved under
`experiments/cas-poc/evidence/`. The benchmark ran from an uncommitted worktree;
code hashes identify the measured implementation independently of commit IDs.

The fixture has 5,000 regular files totaling 375 MiB, plus an internal symlink.
It reuses the earlier deterministic transfer fixture with executable files,
spaces and newline in paths, half-compressible large data, and same-size edits.
Both mechanisms use canonical read-only modes `0444`/`0555`. Source preparation
uses independent replacement inodes before changing shared metadata.

GNU rsync 3.4.1, protocol 32, ran on Linux in the worker container with four
cores and eight threads. Both sender and receiver used local transport with
`--no-whole-file`; no system caches were dropped. The fixture is an empty
content store in the cold case, not a cold disk cache.

Seven cases each ran three methods across one excluded priming round and five
measured rounds. Case and method order rotated. CAS stores were recreated and
seeded for each sample, preventing cross-policy or cross-round blob lending.
All 126 cache snapshots and independent writable execution copies passed full
SHA256, mode, path, and symlink audits. Every original variant and rsync base
remained unchanged after the comparison. Quantiles use linear interpolation.

The CAS prototype verifies every missing file before exclusive atomic blob
insertion. Its key includes SHA256 and canonical mode. It never chmods a shared
inode. Writable execution copies are separate inodes with `0644`/`0755` modes.
Fault tests cover changed source bytes, invalid paths, link escape, insertion
interruption, concurrent insertion, collision winners, mode identity, and
corrupted reuse. Strict rehashing rejects corrupted reused blobs before
publication. Trusted reuse can publish corrupted data if its protected-store
assumption fails; the full output audit detects that failure afterward.

## Results

Median / p95 transfer seconds, excluding external audits and independent copy:

| Case | Rsync | Trusted CAS | Rehashing CAS |
|---|---:|---:|---:|
| Empty store | 0.442 / 0.533 | 1.291 / 1.428 | 1.186 / 1.318 |
| Warm unchanged | 0.241 / 0.337 | 0.142 / 0.151 | 0.525 / 0.561 |
| One small-file edit | 0.252 / 0.329 | 0.180 / 0.188 | 0.568 / 0.600 |
| One large-file edit | 0.272 / 0.300 | 0.192 / 0.235 | 0.538 / 0.585 |
| Divergent bases | 1.611 / 1.691 | 0.712 / 0.827 | 0.878 / 0.899 |
| Retained history | 1.677 / 1.714 | 0.131 / 0.140 | 0.467 / 0.503 |
| Executable-mode change | 0.262 / 0.317 | 0.187 / 0.211 | 0.495 / 0.627 |

Warm trusted reuse saves roughly 0.07 to 0.10 seconds in this fixture's transfer
interval. On those cases, the measured strict reused-blob hashing phase takes roughly
0.32 to 0.40 seconds and makes total transfer slower than rsync. Median independent copy
cost is approximately 0.27 to 0.34 seconds per sample for all methods.
Medians of phase sums are computed from each sample; do not add separate phase
medians to infer a combined median.

Including transfer plus identical execution copying, median warm unchanged
costs are 0.584 seconds rsync, 0.450 trusted CAS, and 0.837 rehashing CAS.
Including both external full audits as well, they are 1.383, 1.299, and 1.663
seconds. For the small edit, those audit-inclusive medians are 1.379, 1.372,
and 1.740 seconds. The audit-inclusive small-edit advantage is negligible here.
The audits establish experiment correctness; they are not a production request
pipeline and do not isolate normal rsync latency.

The retained-history case seeds CAS with both original and divergent blobs,
711.96 MiB in total, while rsync receives only four equivalent divergent bases.
Its benefit includes a wider retained-content set. This is not a comparison
under equal storage or GC budgets. In the divergent case both CAS stores begin
with 375 MiB of divergent content; required new CAS payload is 336.96 MiB.

## Tiny edit inside a large file

A separate targeted job, `d1d7bdaf0edb` / `r13147020580c420`, passed in 40.2 seconds
with peak memory 1,603 MiB. It changed exactly 16 bytes in the 3,925,888-byte
`large/000.bin`, preserving file size and original mtime. It used the same
375 MiB source tree, matching warm bases, five measured rounds per method,
and one excluded priming round. All 18 samples and execution copies passed
the same audits; original source/base inodes remained unchanged.

| Method | Median / p95 transfer seconds | Literal bytes | Sent protocol bytes |
|---|---:|---:|---:|
| Rsync | 0.237 / 0.277 | 1,552 | 170,355 |
| Trusted CAS | 0.189 / 0.201 | 3,925,888 | 3,926,962 |
| Rehashing CAS | 0.468 / 0.526 | 3,925,888 | 3,926,962 |

Rsync reconstructed 3,924,336 matched bytes. CAS needed the full new blob,
about 23 times the sent protocol bytes and 2,530 times the literal bytes in
this probe. Trusted CAS saved approximately 0.048 seconds locally. Its
additional payload could outweigh that gain on a WAN; this probe measures
byte volume but does not measure that network penalty. Audit-inclusive
median totals were 1.262, 1.237, and 1.525 seconds, respectively.

## Interpretation and next evidence

The earlier normal observations measured 3.552-second median rsync on misses.
These local warm rsync medians are around 0.24 to 0.27 seconds. They use a
different source fixture, sender, filesystem, and transport. The difference is
not an attributable overhead or a predicted savings figure.

CAS still needs manifest/control-message transport. The serialized synthetic
manifest is 569,875 bytes for every case, larger than the median 258,337 rsync
protocol bytes in the separate normal-run sample. Those workloads differ and
this POC does not measure compression or wire throughput. Do not count absent
control-message transport as zero production cost. CAS can also lose rsync's
block-level delta reuse when a previously unseen large file changes slightly.
The main comparison's large-file edit changes the complete file. The separate
tiny-edit probe measures the lost block-delta reuse described above.

The two integrity policies expose a real tradeoff. Read-only modes prevent
ordinary accidental writes but do not restrict every process able to change
metadata or edit the worker store. Trusted reuse needs a protected verified
insertion boundary and coordinated references/GC. Per-transfer rehashing costs
full cached-content reads and loses the intended no-read advantage on warm
cases. This POC does not select a production policy.

Before adoption, compare a protected scratch Mac-to-worker path using identical
inputs, actual control messages, and sender/receiver CPU and I/O. Include
equivalent retention budgets, real symlink/mode semantics, and concurrent publishers/GC;
carry the tiny-edit payload penalty into that transport comparison. Crash
durability, live-worktree races,
gateway compatibility, and rollout remain unresolved. None of those paths is
changed by this experiment. Issue #75 remains unreproduced; speculative retries
in #173 remain deferred.
