## Found on the way

* **The worker bundle omitted `engine/writeback.py`** (explicit member list).
  `pandora worker gc` was the first thing to import it. Fixed in 18835df with a
  test that unpacks the bundle and imports its entry points in a clean
  interpreter.
* **`gc --keep 1` deleted the only surfaces golden**: keep counts per
  repository, not per toolchain. Issue #81.
* **Deleting a golden turned the disk quota off.** btrfs marked qgroups
  inconsistent (`drop_subtree_threshold` 3) and the canary wrote 2 GiB into a
  5 GiB quota unrefused. `quota()` now settles qgroups first and `gc` rescans
  after a golden removal (3f2ec81). Full canary with `--mark`: pass, 0 failures.
* **`bin/pandora` did not follow its symlink**: `pandora ps` from outside a
  checkout failed. Fixed in #78; `doctor` checks it.
* **`check` needs `size = "large"`** with the PR's `--concurrency=$PANDORA_CPUS`
  typecheck: a cold run peaks at 6.5 GiB. Warm runs peak near 2 GiB.
* **The surface job's `outputs` name both apps' paths**, so a one-app run
  reports the other app's `test-results` and `playwright-report` as missing.
  Cosmetic; narrow the declaration or accept the notes.
* **The `--update` proposal rewrote all 295 lines of `S0-01.ledger.jsonl`**
  (ids, sequence, event order) although `pnpm journey S0-01` without `--update`
  had just passed against the committed file. Either the runner compares after
  normalisation or the fixture is order-sensitive on the worker. Not judged
  here; the file was restored. Worth a look before anyone commits a worker
  update.
* `same_input_as` matched the `--update` run to the plain run (argv ignored);
  the flaky rule compares argv, so no false flaky mark. Since renamed
  `same_tree_as` (`same tree as <run>` on stderr), which is what it compares.
* The "typical N s" estimate for `check` was 12 s from warm history; the cold
  run took 168 s before the kill. Estimates are medians, not bounds.
