# Pandora v0.1.1 validation contract

This extension targets broad Eichler tests and additional Linux-compatible browser
and database workflows. [Issue #64](https://github.com/gbasin/pandora/issues/64)
tracks implementation and acceptance. The [v0.1 contract](v0.1-contract.md) continues
to define snapshot, scheduling, recovery, cancellation, and publication behavior.

## Commands

| Command at the worktree root | v0.1.1 routing |
| --- | --- |
| `pnpm test:unit`, `pnpm validate unit` | Remote, unfiltered suite |
| `pnpm test:unit <selectors>`, `pnpm validate unit <selectors>` | Local, existing runner |
| `pnpm test:tools`, `pnpm validate tools` | Remote, broad tooling suite |
| `pnpm validate tools <test files>` | Local, focused Node tests |
| `pnpm test:tools <arguments>` | Reject with the focused command above |
| `pnpm test`, `pnpm validate full` | Remote, broad unit/tooling/package tests |
| `pnpm validate agent-web` | Remote, Realtor browser suite |
| `pnpm test:employee-browser`, `pnpm validate employee-browser` | Remote, employee browser integration |
| `pnpm test:browser-integration`, `pnpm validate browser-integration` | Remote, service-backed browser integration |
| `pnpm test:mockup-browser`, `pnpm validate mockup-browser` | Remote, mockup browser tests |
| `pnpm test:postgres api`, `pnpm validate postgres api` | Remote, API PostgreSQL tests |
| The API PostgreSQL forms with `--foundation-only` | Remote, selected API tests |
| `pnpm test:postgres scenarios`, `pnpm validate postgres scenarios` | Remote, scenario PostgreSQL tests |

The same forms with `pnpm run` are supported. Browser suites take no selectors.
Unsupported arguments on remote-only commands stop before execution. The private
launcher changes only its session. It does not install configuration in Eichler.
Literal `npm` commands and direct package commands are outside this routing profile.

## Execution and evidence

Pandora invokes the captured repository's validation planner inside an isolated
container. A private synthetic Git repository supports tools that inspect Git.
It contains the captured source, without local history, remotes, or credentials.
Its commit is execution scaffolding. The submitted source manifest remains the
identity of the tested input.

Container CPU, RAM, and process limits bound each invocation. The adapter also
caps the planner’s Vitest, Jest, and Playwright workers and Turbo task concurrency.
Nested Node test scripts retain their own file concurrency. The broad suite preserves
package tests and their build prerequisites. Package-runner adaptations are recorded
in the result.

PostgreSQL and browser integration use attempt-owned database, pooler, and proxy
containers. Ports stay inside a private network namespace. Browser integration
uses a private sibling of the captured runner with a guarded change to select
external services. The result records the original and adapted runner hashes.
The original runner's test setup, trace sanitization, and teardown remain in use.
The captured source file remains unchanged. A matching attempt receipt, written
only after trace sanitization succeeds, permits trace archives to return. Without
that receipt, the result lists the omitted archives. Failed tests can still return
sanitized traces, screenshots, and error context.

Reports and test artifacts return under the printed attempt evidence directory.
These new workflows do not automatically replace local build directories or source
files. Successful execution requires positive test evidence and verified cleanup.
Preparation failures and interrupted runs must never appear as passing tests.

## Release evidence

Acceptance requires real VM runs for every advertised workflow, failure and empty-test
checks, command routing tests, and cleanup/recovery tests. Coding-agent repair loops
must exercise the same normal commands from local worktrees. Both Codex and Claude
Opus remain evaluation targets. The existing twelve-session capacity evidence remains
the baseline; new runners must use the same resource admission and cleanup mechanisms.

Native iOS builds and simulators continue to run on a Mac. Static checks, standalone
builds, and focused unit tests remain local. Multi-server placement, a Mac worker
backend, arbitrary command offload, and continuous workspace sync are outside this
extension.
