# v0.2 first vertical slice, 2026-09-22

`pnpm journey S0-01` typed in an Acme worktree on the Mac now runs on the
Linux worker and comes back, with every seam real: a `sh` shim in
`~/.local/bin`, a per-user daemon, the repository's own pre-flight validator, a
frozen manifest, rsync into a content-addressed source cache, SSH to a
content-addressed engine bundle, memory admission, an Incus clone of the golden,
Acme's own journey runner, the memory watchdog, artifacts rsynced back into
the worktree, and the command's own exit code. No fake backend anywhere on the
happy path.

Branch `v0.2/assembly`. Everything below was measured on
`ubuntu@WORKER` (4 vCPU, 15.6 GiB, Incus 6.0.5, golden
`golden-2775adec0be404dd`) between 01:30 and 03:00 UTC.

## Architecture as built

| Module | Lines | What it owns |
|---|---|---|
| `pandora/config/` | 748 | `pandora.toml` loader and the argv classifier; produces a plan |
| `pandora/snapshot/` | 357 | manifest freeze, `input_id`, rsync into the worker's source cache, the SSH `Link` |
| `pandora/client/` | 1,727 | daemon, protocol, shim client, enrolment, fallback budget, env filter, settings, the real worker backend |
| `pandora/engine/` | 1,339 | ledger, scheduler, per-run supervisor, the SSH-facing service, the bundle shipper |
| `pandora/executor/` | 828 | the executor interface, the Incus driver, the hog definitions |
| `pandora/cli.py`, `errors`, `exits`, `bin/` | 596 | one `pandora` command, the typed exceptions, the exit table, the two shims |
| **total, excluding tests** | **5,681** | |
| `pandora/tests/` | 1,160 | **135 tests**, `python3 -m unittest discover -s pandora/tests -t .`, 1.4 s |

The executor moved out of `experiments/executor` rather than being copied, with
its 60 tests. The client and repo-config POCs were copied, because both were
substantially rewritten and their own 85 and 77 tests stay green where they are.

Two changes to the code that moved. `MemoryExceeded` is deleted: the POC
declared it and never raised it, and leaving both an exception and a
`Result(outcome='oom')` in place was the ambiguity named as POC blocker 12.
`IncusDriver.supervise` gains an `on_tick` hook, called on the same 0.5 s beat as
the watchdog, which is how an outside cancel reaches a loop that is otherwise
deliberately independent of everything but the cgroup.

### The line the design hangs on

`accepted` is sent to the client only after the engine has admitted the run and
named it. Classification, the repository's validator, the freeze, the transfer
and the submit all happen before that frame, so all of them are provably
non-executing and may still fall back to a local run. Nothing after that frame
may. This is the fallback rule from the direction note made literal in one place
rather than asserted in several.

### Ordering, end to end

    shim (sh, ~5 ms)                 PATH walk, .git walk, one stat, claim match
      pandora.client.shim            env filter, connect, send request
        daemon.serve_run             classify -> repo validator -> freeze -> ship -> submit
          engine submit              ledger claim, admission, spawn a detached supervisor
        <accepted>                   past here the client never runs locally
          engine supervise           prepare -> clone -> inject -> harden -> execute -> collect -> destroy
        daemon.execute               tail the remote log by offset, stream frames to the client
        daemon.deliver               rsync declared artifacts back, then exit as the run exited

## Acme changes

All on `agent/journey-runner-proxy`, committed there, **not pushed**. Two
commits, three edits, all in `tools/validation/`.

### 1. `tools/validation/journey-runner.mjs` -- a `validate` subcommand

Commit `947802b7e`. The owner's rule: a bad flag must be rejected before
anything is queued, not after a container boot.

* Line 46-49 (`const usage`): one line added.

      node tools/validation/journey-runner.mjs validate [<journey id>] [--shard <i/N>]

* Line 61 (`parseRunnerArgs`): `['plan', 'run']` becomes
  `['plan', 'run', 'validate']`.
* Line 99 (`parseRunnerArgs`): `if (command === 'run') {` becomes
  `if (command === 'run' || command === 'validate') {`, so `validate` gets the
  same "one journey or one shard, not both" and shard-default rules as `run`.
* Line 223-227 (`main`), inserted immediately after `parseRunnerArgs`:

      // A dry run: parsing has already rejected an unknown flag, a malformed
      // journey id and an impossible shard, which is everything this file can know
      // without the catalogue. Nothing is spawned and no stack is booted.
      if (options.command === 'validate') return 0;

* Lines 12-16 (the file's own subcommand list): three comment lines describing
  it.

Why: Pandora cannot know what a valid journey selector is, and only this
repository does. `validate` is `run`'s argument check with nothing started.

### 2. `tools/validation/state.mjs` -- keep PATH free of command shims

Commit `947802b7e`. This is the "chain B" fix named in
`notes/client-daemon-poc-2026-09-21.md`, taken as option 1 of the three the POC
offered.

* Inserted directly above `safeEnvironment` (which begins at the old line 83):

      /**
       * Drops any PATH entry that holds a command shim, marked by a `.pandora-shim`
       * file beside it. `safeEnvironment` keeps PATH but not the shim's own recursion
       * guard, so a child spawned from a queued job would re-enter the shim and be
       * routed a second time as if someone had typed it.
       */
      function withoutCommandShims(path = '') {
        return path
          .split(':')
          .filter((directory) => directory && !existsSync(join(directory, '.pandora-shim')))
          .join(':');
      }

* Inside `safeEnvironment`, the final `.map` (old line 104):

      -      .map((key) => [key, source[key]]),
      +      .map((key) => [key, key === 'PATH' ? withoutCommandShims(source[key]) : source[key]]),

`existsSync` and `join` were already imported. Net: 13 lines added, 1 changed.

**Side effect worth stating:** this removes the whole shim directory from PATH
for every Pueue-queued Acme job, not just `pnpm`. On this Mac that directory
is `~/.local/bin`, so anything else a queued job expects to find there is no
longer on its PATH. Nothing in Acme's validation jobs needed it in these
runs, but the narrower alternative (option 2: add `PANDORA_ROUTE_DEPTH` to the
allowlist) is the one to take if that turns out to be false.

### 3. `tools/validation/journey-runner.mjs` -- load the stack lazily

Commit `6dbed7180`. Found by proof 7 and not anticipated.

* Line 37 deleted:

      import { startInstance } from '../stack/instance.mjs';

* Line 289, inside `main`'s `run` branch, replacing `stack = await startInstance(...)`:

      // Imported here, not at the top of the file: `instance.mjs` reaches into
      // the workspace's own dependency graph, so a static import makes `plan` and
      // `validate` fail in a worktree whose dependencies are not installed --
      // which is exactly the worktree a remote runner is asked about.
      const { startInstance } = await import('../stack/instance.mjs');

Why: the second worktree in proof 7 was a fresh `git worktree add` with no
`node_modules`, and `validate` died in `tools/stack/db.mjs` with
`MODULE_NOT_FOUND` before parsing a single argument. A pre-flight check that
requires the install is useless to a system whose entire purpose is that the
install lives on the worker. After the change, `validate` answers in **40 ms**
with no `node_modules` present.

Nothing else in Acme was touched: no `ci.yml`, no `package.json`, no
`AGENTS.md`, no `pandora.toml` in the repository.

## Deviations from the direction note, and why

**The acme configuration is outside the repository.** As agreed for the
slice. `loader.resolve` takes `<repo>/pandora.toml` first and the
enrolment-named path second, so v0.2 final needs no code change -- only the file
moving. The slice's copy lives at
`~/.config/pandora/repos/acme.pandora.toml` and is checked in at
`pandora/config/examples/acme.pandora.toml`.

**`ci_import` is dropped, not trimmed.** Decision 4 of the direction note says
`ci.yml` is linted rather than read, and the slice needs no service containers
at all, so the importer, the pins table, the service library and the network pod
are absent from the loader. They remain in `experiments/repo-config`. A
configuration that still names `ci_workflow` is **refused** rather than ignored,
so nobody can believe facts are being imported that nothing reads.

**Env forwarding is a denylist, not the POC's allowlist.** The POC forwarded
eleven named variables. That would need Pandora edited for every new repository,
which is the coupling v0.2 exists to remove. The caller's environment now travels
minus platform variables and minus secret-*shaped* names, and every drop is
counted on stderr. In these runs that was "dropped 2 secret-looking variables
... CLAUDE_CODE_MESSAGING_TOKEN, SSH_AUTH_SOCK" and "dropped 22 variables that
describe this Mac rather than this job". `SSH_AUTH_SOCK` matches both rules and
is reported under the secret one; harmless, slightly misleading.

**`PANDORA_CPUS` is fixed at admission, so proof 7 measured 4 and 2.** The
direction note's rule -- host cores divided by admitted runs -- is implemented,
but a run admitted while it is alone is told 4 and keeps that hint when a second
run joins. The environment of a started process cannot be rewritten, so closing
this needs either a hint the runner re-reads (a file in `/pandora`, polled) or
admission that waits for a settling window. Named, not fixed.

**`--update` is refused, not implemented**, as scoped. The daemon answers with a
message naming `PANDORA_OFF=1` as the way to run it locally, and the
`--update`-armed writeback outputs are parsed and validated by the loader so the
shape is already there.

**The subdirectory rule is `local`, not `reroot`.** The direction note's open
question listed "drop re-rooting and run locally with a notice" as an option;
the slice takes it, because re-rooting silently changes which files a selector
names.

**The daemon does not turn a broken connection into a verdict.** The first
attempt at proof 9a reported `infra_failed` for a run that was alive and well,
because the daemon's own shutdown tore down its SSH master. Fixed: the follow
loop retries from the recorded remote offset six times, and a shutdown of *this*
daemon leaves the run's row `running` so the next daemon resumes it.

## What is stubbed

* **Retention** deletes attempt *directories* older than the window and leaves
  the ledger rows, because the rows carry `same_input_as` and the learned
  reservations and cost bytes. Verified against the real ledger (`kept 17,
  removed 0`), never yet against an expired one.
* **`--update` write-back**: refused with a message. Out of scope by agreement.
* **Sharding**: one shard per run. The `shards`/`plan` half of the contract
  draft is not in the loader.
* **The launchd plist** is a documented file in `experiments/client/launchd/`,
  never loaded. The daemon ran in the foreground for every proof here.
* **`pandora worker canary`** builds its own hog run rather than being a claimed
  command, because no Acme argv thrashes file cache and inventing one would
  have needed an Acme edit outside the agreed scope. Proof 8 therefore ran
  through the engine API, as the brief allowed.
* **The fake backend** is kept for tests (`FakeDriver` in `test_engine.py`) and
  is never reachable from the daemon: `[backend] mode` is read and only
  `"worker"` is implemented.
* **`--link-dest` deduplicates only when mtimes match.** Repeat runs from one
  worktree hit the cache entirely (`source cache hit`, 0 s ship). A fresh
  `git worktree add` has fresh mtimes, so proof 7's second tree cost a full
  375 MiB transfer and the cache now holds 751 MiB for two nearly identical
  trees. Content-addressed dedup would fix it; rsync's `--checksum` would pay
  for it on every run.

## What remains for v0.2, in order

1. **Close the `PANDORA_CPUS` staleness**: a hint the runner re-reads, or an
   admission settling window. Proof 7 is the measurement that says it matters
   (59 % at N=2 in the executor POC).
2. **The Acme PR**: the three edits above plus `pandora.toml` at the
   repository root, and delete the out-of-repo copy.
3. **Sharding**: `shards`, the `plan` step and the report-against-inventory
   check, which is the half of the two-tier contract the slice did not build.
   `journey-runner.mjs plan` already emits the inventory.
4. **`--update` write-back**, with the "never falls back" rule already in place.
5. **Per-run disk quota and golden GC** -- POC blockers 2 and 3, both untouched.
   The pool is 18 GiB, a golden is ~4 GiB, and the source cache is now growing
   without a bound.
6. **Pin the golden's inputs.** `images:ubuntu/26.04` and `apt-get install` make
   two goldens with the same fingerprint different machines (POC blocker 8). The
   `[worker]` table is honest about the description and silent about the result.
7. **The loop-file pool does not survive reboot** (POC blocker 4).
8. **Watchdog thresholds are still tuned against one hog shape on one host**
   (POC blocker 1). The canary now gates them; a soak across repositories does
   not exist.
9. **Re-attach across a long daemon outage.** The client retries for ~5 s and
   then exits 70 naming the run. `pandora wait` recovers it by hand, which proof
   3 shows works, but nothing does it automatically.
10. **`collect` has no size limit and no streaming** (POC blocker 10); a large
    artifact tree is untried.
11. **The Linux `SO_PEERCRED` branch** of the daemon's peer check is still
    unexercised; the daemon has only ever run on macOS.
12. **Decide the `.pandora-shim` blast radius** -- see the side effect noted
    under Acme change 2.

## Installed state on this Mac

`~/.local/bin/pnpm` and `~/.local/bin/pandora` are symlinks into this worktree
and `~/.local/bin/.pandora-shim` exists, so **the shim is live**. The Acme
enrolment marker has been removed, so nothing routes and the shim is a
transparent passthrough costing ~5 ms; re-enrol with
`pandora enrol <worktree> --config ~/.config/pandora/repos/acme.pandora.toml`
and start `pandora daemon`. The second Acme worktree used for proof 7 has
been removed.
