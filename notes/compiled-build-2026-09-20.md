# Compiled application build evaluation, 2026-09-20

The trial compiled Eichler's actual Ike Home web application from source at
`fbeb008a283221bfedccc8fd47a6f6337d1ddf4d`. It used a disposable bootstrapped worktree
and untracked Docker inputs generated by `experiments/compiled/prepare.py`. No
Eichler change was committed or proposed for merge.

Each build used the normal intercepted Docker command and the shared VM admission
lease. Each image then ran in a separate shell call, checked its compiled HTML
and JavaScript, and returned `apps/borrower-web/dist`. All ten requests passed
with cleanup verified. Source marker assertions checked that returned HTML
changed after the edit and remained present after dependency and toolchain changes.

| Build case | Worker execution | Request time | Source transfer |
| --- | ---: | ---: | ---: |
| First recipe build | 19.9 s | 41.2 s | 2.5 s |
| Identical rebuild | 2.0 s | 24.0 s | 3.4 s |
| HTML source edit | 5.4 s | 27.6 s | 3.2 s |
| Add development dependency | 14.1 s | 35.9 s | 2.9 s |
| Change pinned pnpm version | 17.6 s | 41.2 s | 3.3 s |

Request time ends after remote evidence retrieval, before local output publication
and release acknowledgement. Separate image-run requests took 11.7–17.5 seconds,
including evidence retrieval, with 0.4–0.5 seconds of worker execution. These are
single observations of each case, not latency percentiles or throughput estimates.

The first recipe build had cold application layers and a new pnpm cache namespace,
but a warm source cache, base image, builder installation, and registry connection.
It downloaded 1,124 packages. This was not a new-VM cold-start benchmark.
The identical build reused its build layers and returned the same image ID.
The source edit changed an HTML meta element, reran Vite, and changed the image ID.
Adding `is-number@7.0.0` with its lockfile invalidated installation and compilation.
Because the new development dependency was unused by the application, final output
and image identity legitimately matched the preceding source build.
Changing pnpm from 12.3.4 to 12.3.3 invalidated the toolchain and dependent layers.
Installation reused all 1,163 packages and downloaded none.

The Dockerfile preserves installation-input timestamps while overlaying source.
This matters for pnpm's dependency freshness checks. The final image contains only
the compiled application, verification script, and Node base. Persistent BuildKit
and pnpm caches carry expensive intermediate state. No Docker-in-Docker or local
heavy build is required. Existing local dist contents did not enter the snapshot,
and successive returned generations replaced them successfully.

One setup invocation ran from the Pandora directory instead of the Eichler
worktree. The worker rejected the missing declared Dockerfile and returned a
failure. The five measured builds above used the correct worktree. The generated
input script also refused a second preparation attempt that would overwrite its
existing files.

The useful performance finding is the request overhead: an identical build spent
2 seconds executing and 24 seconds reaching a result. Profile the SSH calls,
source inventory, helper uploads, polling, and evidence transfer before adding
worker capacity. The build context is also broad: BuildKit initially received
about 380 MB. A profile-specific context exclusion policy could reduce that,
but must preserve dependency, source, and secret-exclusion semantics.

This evaluation proves Vite compilation, cache invalidation, and output return.
It does not prove a large native compiler's incremental cache, multiple concurrent
compiled-build agents, interactive previews, or browser behavior. The earlier
agent coding-loop trials remain the evidence for agent behavior. A next evaluation
should measure end-to-end command latency after overhead changes and repeat a
concurrent coding loop with this application build.

Raw measurements, BuildKit logs, provenance, and final recipe are under
`experiments/compiled/evidence/2026-09-20`. At completion, no containers were running
and the worker had 47 GiB free of 96 GiB. Caches and the trial VM remain available.
