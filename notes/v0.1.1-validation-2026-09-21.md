# v0.1.1 validation on 2026-09-21

This trial extends the existing v0.1 worker with broad Acme validation. The
[contract](v0.1.1-contract.md) states the supported command boundary. The
[receipt summary](../experiments/warm/evidence/2026-09-21-v011/summary.json) records
attempt identities, source hashes, command reports, timings, resources, and cleanup.
Raw local evidence is retained under `~/.local/state/pandora/v011-eval`.

## Environment

Final runtime code was committed through Pandora `c1ee59c`. Earlier run receipts
retain their worker-bundle identities; later fixes were rechecked on affected paths.

The target was Acme commit `53c28ae52`, with a clean source manifest of
`bc95ddd2173511c3fbc4c507cc5ba1d528c38dab12fa0d5d358ff0955dcf48c1`.
Each local worktree had its own frozen pnpm install. No Acme configuration or
production source change was committed. Deliberate source defects existed only
in separate evaluation worktrees.

The Linux worker admitted at most two jobs. Its configured capacity was 3,500m
CPU and 13,000 MiB RAM. Each main test container had 1,000m CPU and 4,096 MiB RAM.
Database suites additionally reserved 500m CPU and 768 MiB for their three services.
The execution deadline was 1,500 seconds. The queue budget was 900 seconds.
The checked-in summary includes the complete worker configuration.

The recipe installs Git, Python, Chromium, and WebKit alongside Node and pnpm.
The first dependency image took 164.6 seconds to build. Subsequent runs reused it.
Warm dependency lookup was roughly 0.04 seconds; source transfer, container setup,
application builds, and tests still take time. The image identity was
`sha256:1e1cb3ef6b03e22208773994ae5f64bb6c1d94ffc04ee04da03779b8f874a7db`.

## Agent repair loops

Two real local CLI agents used the normal `pnpm test:tools` command. One was
Codex with `gpt-5.6-terra`; the other was Claude Code with Opus, reported by the
CLI as `claude-opus-5`. Each received an identical defect in
`tools/check-clock-discipline.mjs`: the Date identifier check compared against
`Clock`.

Each agent ran a failing baseline, changed only that comparison to `Date`, and
ran a passing verification. Each baseline recorded 120 passes and eight failures.
Each repaired run recorded 128 passes and one skip. The two failing snapshots
matched each other, as did the two repaired snapshots. There were exactly four
remote attempts, with no cancellation, duplicate submission, or intervention.
All four cleanup receipts were verified.

Opus piped its initial command through `tail`, reducing the displayed failure
context. It still identified the failures and made the correct repair. Neither
agent's final prose included its attempt IDs; the transport and receipts retained
them. The controller was cleaned up after both lanes succeeded. Dirty evaluation
worktrees remain for inspection.

## Failure, artifacts, and recovery

A separate browser-integration worktree deliberately threw in `test.afterEach`
after the normal browser flow. Pandora returned exit 1, both valid trace archives,
two screenshots, and the error context. The sanitizer receipt matched that attempt.
ZIP integrity checks passed. A subsequent clean run also passed and returned both
verified trace archives. The original source was restored in the trial worktree. No source writeback was involved.

The browser adapter writes its sanitizer receipt only after the repository's
sanitizer command succeeds. Tests cover a sanitizer failure and a stale attempt
receipt. Both prevent archive return. Browser results and generated reports remain
under the printed attempt evidence directory; these workflows do not automatically
publish build directories into the source worktree.

During scenario PostgreSQL execution, the evaluator killed only its owned local
transport child. The remote job continued. `pandora wait <id>` returned exit 0
and the same attempt identity, without resubmitting source. A separate running
browser-integration request was explicitly cancelled. It returned exit 130 after
verified service and private-network cleanup.

## Findings corrected during the trial

The first tooling receipt failed to recognize Node's default spec output despite
successful tests. Direct Node tests now request TAP explicitly; wrapper reports
also recognize spec summaries. Skipped-only success is rejected. Failed commands
retain their actual failure when no JSON report was produced.

The first full API PostgreSQL run failed at the letters runtime's database reset.
That test deliberately accesses `postgres:5432` through wsproxy. The original
Pandora adapter provided only the PgBouncer alias and proxy route. PostgreSQL
validation now has both exact destinations, matching the repository's local
Compose topology. The alias and allowlist change apply only to this workflow;
browser and journey service configuration remain unchanged. The rerun completed
the full invariant suite and returned exit 0 after verified cleanup.

The full-suite adapter now forces Turbo test execution. Cached test logs cannot
stand in for a fresh package test run. The receipt records that adaptation and the
separate, capped web Jest invocation. The final rerun reported three forced
package tasks and zero cached tasks.

Local source capture was usually about four to six seconds, but the same 4,803-file,
roughly 372 MiB snapshot took 61–109 seconds in several runs. A read-only check found
fast Git enumeration and no captured dependency directory or nested worktrees.
The cause of those pauses is unresolved. Capture now prints a heartbeat after ten
seconds, explicitly saying that remote validation has not started. Tests verify
that the feedback thread stops on success and failure.

## Intermittent target-repository test failure

The final full-suite rerun returned exit 1. All prior steps passed, including three
forced Turbo package tasks with zero cache hits. Agent Jest passed 502 of 503 tests.
`apps/agent/__tests__/roster-tasks-closing.test.tsx:49` timed out waiting for
`File updates`; its rendered tree still showed `Loading your view`. The same source
passed in the earlier complete run. The failed run recorded zero OOM kills.

A separate admitted probe selected only this unchanged test through a trial-only
planner override. Three separate Jest processes passed under the same CPU/RAM
limits. The first used a cold transform cache; the next two reused that cache.
This probe is not counted as a full-suite pass. Its source digest differs only
because of the evaluation planner change, which was restored afterward.

[Acme #1318](https://github.com/getacme/acme/issues/1318) records the
intermittent failure. The exact cause remains unresolved. No timeout, assertion,
or product source was changed to make it pass. Both complete-run outcomes remain
in the summary. The final rerun therefore verifies fresh execution and accurate
failure delivery; it does not establish a second all-green suite.

## Scope of the evidence

Python regression runs passed 281 warm-runtime tests and 99 routing tests during
integration. Final affected Python checks passed 36 tests. The final Node adapter,
service, and artifact checks passed 14 tests. These cover malformed requests,
empty-test rejection, failure evidence, service ownership, OOM reporting, cleanup,
and sanitizer-bound artifact return.

The prior twelve-agent v0.1 trial remains the concurrency baseline. This extension
ran two real repair agents plus scripted validations on the same admission system.
It did not repeat the twelve-agent trial. The user subsequently reported the Mac
was responsive enough during the v0.1 trial; no new subjective responsiveness
claim is made for this extension.

Native iOS compilation and simulator execution still require a Mac. This release
has no Mac backend, multi-server placement, continuous sync, or interactive preview
forwarding. Command routing is session-local and can be bypassed by absolute
executables, manual PATH changes, or unsupported direct package commands.

The [final resource audit](../experiments/warm/evidence/2026-09-21-v011/final-resources.json)
found no trial-owned containers or networks, no running/waiting scheduler requests,
no active trial units, and no running Docker containers. The two-agent controller
was cleaned up. Dependency images and retained evidence remain warm on the VM.
