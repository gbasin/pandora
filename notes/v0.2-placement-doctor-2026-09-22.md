of "What others have that Pandora lacks" in `notes/prior-art-2026-09-22.md`,

## What exists

| Piece | Where | What it does |
|---|---|---|
| `pandora run --local -- <cmd>` / `--remote` | `cli.py`, `client/shim.py` | mutually exclusive; passed to the shim client as `--where` |
| `PANDORA_WHERE=local\|remote <cmd>` | `client/shim.py`, `bin/pnpm`, `client/passthrough.py` | the same request from the shim path. The flag wins when both are given. Empty is "not asked". Any other value is exit **64** with `pandora: PANDORA_WHERE=<v> is not a placement; use local or remote (or unset it)`, before the daemon is asked anything |
| the decision | `client/placement.py` | `decide(job, plan, override)`: the lane, a possibly adjusted plan, the record, the lane reason. Refusals are `Refused` with code `placement`, exit 64 |
| the daemon's use of it | `daemon.serve_run` | one block replacing `if job['where'] == 'local'`, before the `--update` refusal and before the validator |
| no fallback from `--remote` | `daemon.fall_back`, `shim.no_daemon` | every pre-accept failure of an explicit `remote` is exit **70**, code `placement-unavailable`; nothing is admitted to the local lane |
| the record | `Run.save`, `Run.finish` | `meta.json` and `result.json` carry `placement: {where, declared, override, overridden}`; an override that moved a run sets the lane reason `override:local` / `override:remote`, in the field a fallback writes `fallback:<cause>` into |
| `pandora stats` | `client/stats.py` | `overrides: {local\|remote: {asked, moved, unclaimed}}`; text line `overrides: local x2 (1 moved, 0 on unclaimed), ...` |
| `pandora result` | `cli.render_result` | `placed local by override; the job says remote` |
| `pandora doctor [--json]` | `client/doctor.py`, `cli.py` | nine checks, one line each, exit 1 on any `fail` |
| launcher fix | `bin/pandora`, `bin/pnpm` | both follow their own symlink chain (a `readlink` loop, relative targets resolved against the link's directory, 40 hops) to find the package |
| the daemon's package | `daemon.PACKAGE_HOME` | in `daemon.json` and in the `pong` frame, beside the cached worker-health reading, so the doctor can compare packages and read the worker without `ps` |

## The override behaviour table

"moved" means the override changed the lane. Every refusal is before the
validator, the freeze and the queue; nothing runs anywhere.

| Job `where` | Override | Claimed | `--update` armed | Result |
|---|---|---|---|---|
| remote | none | yes | no | worker; fallback policy by size class as before |
| remote | none | yes | yes | refused as before (`--update` write-back is not in this build; another branch is adding it) |
| remote | `local` | yes | no | local lane, job's size class, reason `override:local`. `fallback = "refuse"` and size `large` do not apply: this is not a fallback |
| remote | `local` | yes | yes | local lane; the run writes its write-back paths in place, which is what a local run does |
| remote, `shards` declared | `local` | yes | any | **64**: sharded across worker instances (and, with a `plan`, the run step uses what the worker's plan step built -- acme's surface `run` is `... --no-build`) |
| remote | `remote` | yes | any | as with no override, except that no pre-accept failure falls back: **70**, `placement-unavailable` |
| local | none | yes | n/a | local lane as before |
| local | `local` | yes | n/a | local lane; recorded as asked, not moved |
| local | `remote` | yes | n/a | worker, with `git = "synthetic"` forced (see below), reason `override:remote`. Worker down, unreachable, or any other pre-accept failure: **70**, never the local lane |
| local, `singleton` | `remote` | yes | n/a | **64**: it holds resources on this machine (the dev stack's ports) |
| local, `evidence` outputs | `remote` | yes | n/a | **64**: a worker run writes the evidence on the worker and nothing brings evidence home |
| any | `local` or `remote` | **no** | n/a | runs unchanged as if the shim were absent; one passthrough-log line carrying `override` (reason `override-ignored` for a light command, `unclaimed` for a heavy one, `passthrough` when the daemon declined it); counted as `unclaimed` in `pandora stats`, not in "local, not routed" |
| any | any | yes, daemon not running | any | `remote`: **70**, nothing runs. `local`: the existing no-daemon policy by size class under the slot budget, because the local lane is the daemon |
| any | invalid value | enrolled repo | any | **64** before anything else |
| any | any, with `PANDORA_OFF=1` | any | any | `PANDORA_OFF` wins; the shim execs the real pnpm before it reads anything |

### A local job sent to the worker gets a synthetic repository

The loader refuses `git = "synthetic"` on a local job, because a local job runs
in a real checkout. So a local job cannot declare that it needs git, and acme's
`validate-node` and `unit` both run `pnpm validate`, whose planner calls
`git rev-parse HEAD`, `git diff HEAD` and `git ls-files`. A worker run arrives
without `.git`. `--remote` therefore forces `git = "synthetic"` rather than
guessing that the job never touches git: ~3 s on the worker against a run that
would fail for a reason nobody typed. It needs `git` in the golden, which
acme's `[worker].packages` has.

### What acme's tools pass

Nothing changes in how they call `pnpm`. To place one command:

    PANDORA_WHERE=local pnpm journey S0-01 --update     # writes fixtures in place, through the lane
    PANDORA_WHERE=remote pnpm validate node x.test.mjs  # a local job, on the worker

No acme edit is needed. The variable is read once, by the outermost shim, and
travels to the daemon as a request field. It never reaches the run: `envfilter`
drops every `PANDORA_*` name from what is forwarded, and the local lane's
`child_environment` builds its environment from an allowlist plus
`PANDORA_ROUTE_DEPTH=1`, so a nested `pnpm` inside `validate.mjs` or
`journey-runner.mjs` neither routes nor sees the override. (acme's own
`safeEnvironment` in `tools/validation/state.mjs` is an allowlist without
`PANDORA_*` too, read-only check.)

## `pandora doctor`

Each check is independent; the daemon-dependent ones fail with the reason when
there is no daemon. It asks the daemon only `ping`: `ps` samples the pause gate
and can move its counters, and `stats` can trigger a worker poll.

| # | Check | Proves | Fail | Warn |
|---|---|---|---|---|
| 1 | `pnpm on PATH` | the first `pnpm` is Pandora's shim, and the real pnpm found behind it by the shim's own walk (skip the shim's directory as a string and `PANDORA_SHIM_DIR`) | no pnpm; another pnpm first; no real pnpm (the shim exits 127); the next pnpm is a second Pandora shim under another spelling | the real pnpm is corepack, Volta, mise, asdf, nodenv or fnm |
| 2 | `recursion guard` | `PANDORA_ROUTE_DEPTH` is not set in this shell | set: inside a Pandora run, or leaked; nothing routes | |
| 3 | `pandora on PATH` | the `pandora` on PATH, run from `/` without `PYTHONPATH`, imports a package, and which one | it cannot import | a different package from this doctor's; no `pandora` on PATH |
| 4 | `daemon` | a daemon answers `ping` on the socket the shim will use (the marker's `sock`, else `<state>/client.sock`) with this client's protocol | nothing there; a socket nobody listens on; a protocol refusal | it runs another package; it predates `doctor` and does not say |
| 5 | `worker` | the daemon's cached health reading, never a new poll | daemon unreachable; worker `down` | `degraded`, `unknown` or stale |
| 6 | `repository`, `marker home`, `marker socket`, `daemon enrolment` | the git common dir holds a marker; the marker's `home` still has the package; the marker routes to this state; the daemon's `[[repos]]` has the repository | not in git; not enrolled (with `pandora enrol <root>` when a `pandora.toml` is there); `home` gone; no `[[repos]]` entry, so the daemon passes everything through | the marker's socket differs from the doctor's state |
| 7 | `working directory` | cwd is the worktree root | | a subdirectory, citing the re-root rule and exit 64 |
| 8 | `variables` | `PANDORA_OFF`, `PANDORA_WHERE`, `PANDORA_SHARDS`, `PANDORA_KEEP_GOING`, `PANDORA_SHIM_DIR`, `PANDORA_HOME`, `PANDORA_CONFIG`, reported as `info` | `PANDORA_WHERE` is not a placement | |

## The launcher bug, and what the doctor said on this Mac

`~/.local/bin/pandora` is a symlink to `<checkout>/bin/pandora`. The launcher
took `$0`'s directory, so `PYTHONPATH` became `~/.local` and `pandora ps` failed
with `No module named 'pandora'` from any cwd that is not a checkout -- it
worked inside one only because `python -m` puts the cwd on `sys.path`. `bin/pnpm`
had the same fallback (`$selfdir/..`) but reaches it only when the marker has no
`home` line, which `pandora enrol` has always written; it now resolves the link
there too, and only there, so the non-enrolled path still forks nothing. The
tests run both scripts through an absolute-then-relative link chain from a temp
cwd, and fail against the old scripts (3 of 4).

Run read-only from `~/Code/acme-wt/journey-runner-proxy` against the live
daemon, with this branch's package:

    warn  pnpm on PATH       shim ~/.local/bin/pnpm, real pnpm /opt/homebrew/bin/pnpm
                             (-> .../corepack/dist/pnpm.js); the real pnpm is a corepack shim
    ok    recursion guard    PANDORA_ROUTE_DEPTH is not set
    fail  pandora on PATH    ~/.local/bin/pandora cannot import its package from outside a
                             checkout: ... No module named 'pandora'
    warn  daemon             pid 97784 on ~/.local/state/pandora/v02/client.sock, protocol v2;
                             it predates `doctor` and does not say which package it runs
    warn  worker             worker: degraded (disk 8.6 GiB free; worker state is unproven;
                             polled 10s ago), from the daemon's cache file
    fail  repository         not enrolled (no ~/Code/acme/.git/pandora-enrolled)
    ok    working directory  the worktree root
    ok    variables          none of PANDORA_OFF, PANDORA_WHERE, PANDORA_SHARDS set
    ok    shim markers       .pandora-shim beside the shim only

The first failure is the launcher bug, still live because `~/.local/bin` points
at the `v02-assembly` checkout, which does not have the fix. The second is
expected: the slice removed acme's marker. The corepack warning is real: the
pnpm behind the shim is corepack's, which picks a pnpm per directory from
`packageManager`.

## Found in the existing code, contradicting the notes

* `notes/v0.2-fallback-2026-09-22.md`, "Subdirectory invocations" and "Where the
  tension is", say a subdirectory invocation naming a path *passes through*
  locally. The code refuses it with 64 (`classify.classify`, `shim.
  subdirectory_offender`), as `--help`, the example config and
  `docs/agents-paragraphs.md` say. The note is stale.
* The `bin/pnpm` header says "Anything that goes wrong before the daemon says
  `accepted` ends in a local exec". Since the fallback note, a live daemon's
  verdict is final and the client decides only when the daemon is gone.
* `exits.PRE_ACCEPT`'s comment says the client "is free to run the command
  locally" on any of those codes. Same staleness.
* The brief for this work says Python 3.10; `settings.py` and `loader.py` import
  `tomllib`, which is 3.11. `/usr/bin/python3` on this Mac is 3.9 and cannot run
  Pandora; the launcher tests pin `PANDORA_PYTHON` for that reason.
* The slice note says the installed symlinks point into "this worktree"; they
  point into `v02-assembly`, and the live client state is `~/.local/state/
  pandora/v02`, not `default`.

## Unverified

* **Nothing ran against the worker.** No override has submitted anything to a
  real engine; `--remote` with a synthetic repository for a local job is tested
  against a recording fake worker only.
* **Nothing ran through the live daemon** except `doctor`'s `ping`, read-only.
  The running daemon (pid 97784) predates this branch, so its `pong` has no
  `home` and no health; the doctor fell back to its cache file, as designed.
* A refused override (64) leaves no run and no log line, so `pandora stats`
  cannot count refusals.
* The version-manager detection is by path fragment. A corepack that is not
  under a path containing `corepack` would pass as a plain pnpm.
* The launcher's `readlink` loop is tested on macOS only.
